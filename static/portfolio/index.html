Why

같은 경기를 보는 사람이 다섯 부류입니다

전술 도구가 감독에게만 맞으면 팬은 못 쓰고, 팬 앱에 맞추면 분석가가 수치를 믿지 못합니다. 모든 기능을 아래 다섯 시선으로 점검하고, 화면마다 "근거" 줄에 지표 정의를 적었습니다.

감독

경기 준비에 바로 쓰는 프리매치 스카우팅 요약과 포메이션·화살표 전술판

코치

팀 형태, 슛맵, 히트맵을 같은 화면에 놓고 코치진이 함께 보는 분석 탭

선수

내 포지션의 활동 범위와 동선, 같은 포지션 선수 대비 백분위

분석가

90분 환산, 운 보정(xG) 순위, 출처가 다른 데이터를 섞지 않는 원칙

팬

경기 후 요약 카드, 팀 비교, 팀 컬러 29종으로 구분되는 화면

How it works

시스템 구조

수집, 저장, 서빙, 화면이 한 방향으로 흐릅니다. 외부 API 장애가 화면까지 번지지 않도록 단계마다 격리했습니다.

영역선택이유
백엔드Python, Flask, SQLite읽기 위주 분석 서비스라 단일 파일 DB로 충분하고 백업·복원이 단순합니다.
프런트Vanilla JS, Canvas, CSS전술판의 드래그·화살표를 프레임워크 없이 직접 제어하기 위해 선택했습니다.
캐시인메모리 TTL + 세대 마커데이터 갱신 후 워커 여러 개가 같은 시점에 캐시를 비우도록 파일 마커 하나로 통일했습니다.
운영nginx, gunicorn, systemdRocky Linux 서버에 CI로 배포하고 일일 백업과 헬스체크를 둡니다.
Problem solving

실제로 겪은 문제와 해결

스포츠 데이터는 틀린 숫자가 곧 틀린 결론입니다. 아래는 운영하면서 직접 찾고 고친 사례입니다.

2026.08 – 11데이터 수집

데이터 원천이 차단됐을 때, 조용히 실패하는 수집기를 먼저 고쳤습니다

문제
SofaScore가 403 챌린지로 막혔는데 수집 스크립트는 정상 종료(exit 0)를 반환해, 8월부터 선수·경기 상세 수집이 끊긴 걸 11월에야 알았습니다.
해결
수집 전 상태를 점검하는 probe, 부분 실패를 구분하는 종료 코드(0/1/2), 화면 헤더의 "일부 미수집" 배지, 소스별 공백 감사 스크립트를 추가했습니다. 이어서 K리그 공식 API로 득점·카드·교체·패스·라인업·히트맵을 복구하는 크롤러를 만들었습니다.
결과
복구 후 감사에서 16개 소스가 모두 정상 범위로 돌아왔고, 이후 수집은 주간 크론으로 자동 처리됩니다.
2026.06시각화 정확도

히트맵 절반이 좌우로 뒤집혀 있던 버그

문제
원본 좌표가 이미 팀 기준으로 정규화돼 있는데 원정 경기에서 한 번 더 반전하고 있었습니다. 골키퍼 좌표가 반대편(x>80)에 찍힌 비율이 44%였습니다.
해결
변환 로직을 통과형으로 바꾸고, 골키퍼 위치로 방향을 검증하는 기준을 세웠습니다.
결과
반대편 좌표 비율이 44%에서 0%가 됐습니다. 같은 시기 events 스코어 12경기의 홈·원정 반전도 공식 JSON과 대조해 찾아 교정하고, 이후 동기화 때 자동으로 바로잡히도록 했습니다.
2026.11데이터 정합성

출처가 다른 데이터를 섞지 않고, 이름 오기 153건을 되돌릴 수 있게 고쳤습니다

문제
공식 선수 기록(871경기)과 SofaScore는 지표 정의가 달라 합치면 수치가 왜곡됩니다. 또 선수 이름 오기로 박승욱, 권완규 같은 선수가 검색 결과 0건이었습니다.
해결
공식 기록은 별도 테이블로 분리하고 화면에서 출처를 선택하게 했습니다. 이름은 공식 ID 매핑, 로마자 표기, 포털 생년월일 세 근거가 일치하는 건만 자동 교정했고, 근거가 약한 8건은 사람이 검토한 뒤 적용했습니다.
안전장치
적용 전 DB 백업, name_ko 외 컬럼 해시 불변 검증, 단일 트랜잭션, 롤백 JSON을 모두 두었고 기본 동작은 dry-run입니다.
2026.11운영 안정성

6개월 가까이 실패하던 일일 백업을 발견했습니다

문제
백업 스크립트가 git에 실행 권한 없이(100644) 저장돼 있어, 배포 때마다 권한이 빠져 5/15부터 매일 03:00 백업이 실패하고 있었습니다.
해결
git 파일 모드를 100755로 고치고 배포한 뒤 수동 실행으로 정합성(quick_check, 행 수)을 확인했습니다. 다음 날 03:00 크론이 스스로 성공하는 것까지 로그로 검증했습니다.
교훈
백업은 "스크립트가 있다"가 아니라 "복원할 수 있는 파일이 오늘 생겼다"로 확인해야 합니다.
2026.11책임 있는 수집

외부 사이트 부하를 줄이는 방식으로 백필했습니다

문제
공식 사이트 내부 API를 백필하던 중 요청 간격이 짧아 봇처럼 보일 수 있다는 지적을 받았습니다.
해결
즉시 중단하고 요청 간격을 0.8초에서 3초로 늘려 이어받기로 재시작했으며, 원장 테이블로 중단된 지점부터 재개되게 했습니다. dry-run도 실제로 호출하므로 시험은 소량으로만 합니다.
결과
2026·2025 시즌 891경기 중 871경기를 저장했고, 실패분은 주간 작업이 재시도합니다.
Quality

품질을 지키는 방식

  • 스모크 테스트 121개 항목(qa_check.py): API와 DB의 정합성을 한 번에 점검합니다. 득점 합이 스코어와 맞는지, K1에 플레이오프가 섞이지 않았는지 같은 도메인 규칙도 검사합니다.
  • 5회 자기 점검 루프: 초안, 정확성, 보안·안정성, 연관 파일, 최종화 순서로 매 작업을 점검하고 결과를 checklist/에 남깁니다.
  • 보안: 모든 쿼리는 파라미터 바인딩만 쓰고, 템플릿 인라인 스크립트를 제거해 CSP를 강화했습니다. 쓰기 API에는 파일 크기 상한과 nginx 빈도 제한을 걸었고 업데이트 트리거는 시크릿이 없으면 비활성입니다.
  • UI 기준: 팀 컬러 29종을 CSS 변수로 관리하고 대비비 4.5:1 이상, 키보드 포커스, 색상 외 정보 전달을 지킵니다.
  • 기록: 일자별 작업 로그와 재개 가이드를 두어, 새 환경에서도 문서만 보고 작업을 이어갈 수 있습니다.
