# 영입 추천 — 후보 목록(숏리스트)·비교·CSV 내보내기 (설계)

2026-11-24 · 1단계(2단계 = 해외 후보 포메이션 사실 표시, 별도 설계)

## 왜
영입 추천 표는 매번 새로 계산되고 화면을 떠나면 사라져, 실제 영입 회의 흐름
("후보 3~5명 추리기 → 나란히 비교 → 코치진과 공유")에 쓸 수 없다(P1·P5).
팬에게는 '내 영입 위시리스트' 자체가 재미(P2).

## 목표 / 비목표 / 반목표
- 목표: 모든 후보 표(포지션 보강·플레이 보강·비슷한 선수·해외 후보)에서 ☆로 담기 →
  팀별 후보 목록 → 나란히 비교 → CSV 내보내기.
- 비목표: 서버 저장·기기 간 동기화·다른 사용자와 공유 링크(로그인 OFF라 사용자 구분 불가).
- 반목표: K리그 후보와 해외 후보를 같은 지표 열에 섞어 "같은 기준"처럼 보이게 하는 것(P4).
  추천/적합도 계산 공식 변경(Red) 없음.

## 접근 방식 (검토한 것)
- **A. 브라우저 저장(localStorage) + 비교 패널 + CSV — 채택.** 서버·DB·API 변경 없음.
  단점: 기기 간 공유 안 됨 → CSV로 대체.
- B. 서버 저장(새 테이블) — 스키마 변경(Red) + 사용자 식별 불가로 부적합.
- C. 기존 saves/squads 형식 재사용 — 직렬화 형식 무단 변경 금지 규칙에 걸림.

## 설계
- **저장 단위**: 우리 팀(slug)별 목록, 최대 10명. 키 `tt_recruit_shortlist_v1` 한 개에
  `{ [teamSlug]: [entry...] }`. 모든 읽기·쓰기 try/catch(사생활 모드 등에서 실패해도 화면 정상).
- **entry = 담는 순간의 스냅샷** (국내·해외 후보를 함께 다시 조회하는 API가 없어서 —
  재조회 대신 '담은 날짜'를 보여 준다):
  `src`(kr|os), `id`(국내 player_id / 해외 이름+팀), `name, team, league, age, mins, goals, assists,
  detail(세부 포지션 라벨), score(종합), fit(적합도·유사도·보정 중 그 표의 대표 점수)과 그 이름,
  metrics: [{label, pct}] (그 표에 보이던 지표 백분위), mode(어느 추천에서 담았나), saved(YYYY-MM-DD)`.
- **UI** (`recruit.js`, 표 구조 유지):
  - 각 후보 행 맨 앞에 ☆/★ 토글 버튼(`aria-pressed`, `aria-label="후보 목록에 담기: 이름"`).
  - 모드 탭 줄 오른쪽에 `후보 목록 (N)` 버튼 → 아래로 펼치는 비교 패널.
  - 비교 패널: 국내 후보 / 해외 후보 **구역 분리**(P4). 구역마다 카드 열(선수 1명=1열):
    이름·소속·리그·나이·출전·골·도움·세부 포지션·대표 점수·지표 백분위 막대·담은 날짜·빼기 ✕.
    "지표 정의가 다른 리그(해외 API)라 국내 후보와 수치를 직접 비교하지 마세요" 안내 한 줄.
  - 버튼: `CSV 내보내기`, `모두 비우기`(confirm).
  - 10명 초과 시 토스트/안내 문구로 막음.
- **CSV**: UTF-8 BOM(엑셀 한글), 열 = 구분·이름·소속·리그·나이·출전·골·도움·세부 포지션·
  점수 이름·점수·지표(라벨:백분위; 세미콜론 묶음)·추천 방식·담은 날짜. 파일명
  `영입후보_{팀}_{YYYYMMDD}.csv`. **수식 인젝션 방어**: 셀이 `= + - @ \t \r`로 시작하면 앞에 `'`.
  따옴표 이스케이프(`"` → `""`).
- **보안(P7)**: 저장값을 다시 그릴 때도 전부 `ttEsc` — localStorage는 사용자 조작 가능한 입력.
  숫자는 `Number()` 검증, 형식 틀린 entry는 버림.
- **CSS**: 기존 `rc-*` 토큰·색 재사용, ☆ 버튼 hover/active/focus-visible 정의, 대비 4.5:1,
  최소 12px. `style.css`·`recruit.js` 캐시 버전 올림.
