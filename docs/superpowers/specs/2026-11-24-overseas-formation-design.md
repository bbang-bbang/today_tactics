# 해외 후보 — 포메이션 사실 표시 (설계)

2026-11-24 · 영입 추천 2단계 (1단계 = 후보 목록, `2026-11-24-recruit-shortlist-design.md`)

## 왜
감독·코치(P1·P5)가 해외 후보를 볼 때 "이 선수가 우리 팀 시스템(3백/4백)에서 뛰어 봤나"를 묻는다.
지금은 세부 포지션(윙어 등)만 보여 맥락이 없다.

## 목표 / 비목표 / 반목표
- 목표: 해외 후보마다 **선발로 뛴 팀 포메이션 사실**(주 포메이션, 3백/4백 계열 선발 수)과
  우리 팀 주 포메이션 계열과의 일치 여부 표시.
- 비목표: 국내 후보 포메이션 표시(별도), 수집기·스키마 변경, 재수집.
- 반목표(P4): 포메이션 일치를 **점수·순위에 섞지 않는다**(근거 없는 가중치 = Red). 사실만 보여 준다.

## 접근 방식
- **A. 저장된 grid로 복원 — 채택.** 해외 리그 DB `match_lineups.formation_slot`("줄:열")을 경기·팀(event_id, is_home)별로
  모아 줄마다 인원을 세면 포메이션(예: 2줄 4·3줄 3·4줄 3 → `4-3-3`). 수집기·스키마·API 호출 변경 없음.
- B. 수집기에 formation 컬럼 추가 + 재수집 — 스키마 변경(Red)·API 호출 수천 건. 불필요.
- C. 적합도 점수에 가중 — 반목표 위반.

## 설계
- **백엔드 `main.py`**
  - `_formation_from_grids(grids) -> str|None`: 11개 grid의 줄 번호별 인원, 1줄(GK) 제외하고 `-`로 연결.
    11명이 아니거나 1줄 인원≠1, 파싱 실패면 None.
  - `_formation_family(f) -> "3백"|"4백"|None`: 첫 숫자 3·5 → "3백", 4 → "4백".
  - `_overseas_rows`: 리그별로 선발 grid를 한 번 읽어 (event, is_home)별 포메이션 → 선수별
    `formation_main`(최빈 포메이션), `fam_starts` {"3백": n, "4백": m} 추가. 실패·데이터 없음이면 None/{}.
  - `/api/overseas-recruit`: 선택 인자 `team`(K리그 팀 slug, 형식 검증) → 그 팀의 현재 시즌 주 포메이션
    (`_brief_formations` 재사용) → 응답 `team_formation: {formation, family, games, of}` (없으면 null).
    후보 행에 `formation_main`, `fam_starts`, `fam_match`(우리 팀 계열 선발 수/전체, 팀 정보 없으면 null).
    **점수·정렬 불변.** notes에 "포메이션은 사실 표시만, 점수에 반영 안 함" 한 줄.
- **프런트 `recruit.js`**
  - 해외 후보 요청에 `team=_team`.
  - 표 위 한 줄: `우리 팀 주 포메이션 3-4-3 (3백, 18경기 중 12)`.
  - 후보 이름 아래 보조 줄에 `4-3-3 위주 · 3백 선발 2/18`. 우리 팀 계열 선발이 0이면 `⚠ 3백 선발 경험 없음`
    (아이콘+문구, 색만으로 전달 금지). 라인업 데이터 없으면 표시 생략.
  - 후보 목록 담기 시 `detail`에 `윙어 · 4-3-3 위주` 형태로 함께 저장(스냅샷 형식 불변).
- **테스트**: Python 단위(복원·계열·경계값) — `analysis/verify_overseas_formation.py`(읽기 전용, 합성 DB),
  `qa_check.py`에 응답 키 확인 1줄. 브라우저 1280·375 Chromium·Firefox.

## 확인 기준
- 합성 grid: 4-3-3·3-4-3·5-3-2·4-2-3-1 복원, 10명/GK 2명 → None.
- 운영 데이터(배포 후 API): 리그별 표본 후보의 `formation_main`이 상식적인 값, 응답 시간 큰 증가 없음.
- 점수·순위가 변경 전과 동일.
