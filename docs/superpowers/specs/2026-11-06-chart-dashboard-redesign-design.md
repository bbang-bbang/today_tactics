# 차트·대시보드 전면 개편 설계 (TERA CHART 도입)

- 작성일: 2026-11-06
- 범위: 인사이트 · 팀 분석/비교 · 선수(리포트/분석/비교) · 경기예측 · 경기 리포트 — 전 화면 일괄
- 표기: **[사용자]** = 사용자가 정한 것, **[판단]** = Ralph(웹디자이너 관점)가 위임받아 정한 것 — 사용자 검토 대상

## 1. 왜 하는가

**[사용자]** "인사이트를 도출하는 방식이 전부 막대 그래프라 단순하다. 전문가·분석가·팬 누구에게도 UI가 편하지 않다."

현황 진단 (2026-11-06 실제 화면 캡처 기준):

| 화면 | 문제 |
|------|------|
| 인사이트 › 심화 | 카드 18개가 전폭 1열로 쌓여 **세로 23,000px**. 리그 '전체'면 K1·K2 표가 연속 2번. 실제 차트는 Chart.js 2개뿐, 나머지는 HTML 표 + CSS 막대 |
| 팀 분석 › 결과 분석 | 시즌 득실 트렌드가 157경기 전체를 한 줄로 그려 판독 불가. 나머지 대부분 세로 막대/표 |
| 선수·예측·비교 | 막대(가로/세로)·표·레이더 위주. 분포·비교·불확실성 표현 수단이 없음 |

공통 근본 원인:
1. **질문과 차트 형태 불일치** — "실력 대비 운은?"(두 변수 관계)을 표로, "차이가 진짜인가?"(불확실성)를 표 속 가는 선으로 표현.
2. **시각 계층 부재 (P6)** — 모든 카드가 같은 크기·무게. 요약(KPI) 층이 없어 "3초 안에 핵심"이 불가능.
3. **도구 한계** — Chart.js 기본형(bar/line/radar/scatter)만 사용.

## 2. 목표 / 비목표 / 안티목표

**목표**
- G1. 각 인사이트의 *질문*에 맞는 차트 형태로 교체 (아래 §5 매핑).
- G2. 대시보드 레이아웃 도입: **요약 KPI → 테마 필터 → 중요도별 크기의 카드 그리드** (A안).
- G3. 카드 문법 통일: **질문 → 한 줄 해석 → 차트 → (접힌) 근거 표·방법론**. 분석가용 원본 수치는 하나도 잃지 않는다.
- G4. 인사이트 심화 탭 길이 대폭 축소 (목표: 1440×900 기준 스크롤 5화면 이내).
- G5. 차트 라이브러리를 TERA CHART로 일원화하되 **어댑터 1곳**을 거쳐 교체 가능하게.

**비목표**
- **기존** API 필드·통계 계산식 변경 없음 (P4 Red 회피). **[사용자] 새 필드 추가(additive)만 허용** — §4.5. 프런트엔드는 새 통계를 계산하지 않는다(모든 통계는 서버).
- 전술판 Canvas 코어(드래그/화살표/애니메이션), 히트맵 좌표 변환(`k2heatmap.js`), 패스 네트워크 렌더러(`pass_network.js`), 팀 형태(`renderShape`) 경기장 그림은 변경 없음.
- 라이트 모드 신설 없음 (현 다크 테마 유지).
- 해외리그 탭(비활성) 대상 아님.

**안티목표 (기술적으로 돌아가도 실패로 간주)**
- 화려하지만 해석이 느려지는 차트 (3D, 장식용 애니메이션 남발). 3D·WebGL 차트 타입 사용 금지.
- 표를 없애서 분석가가 정확한 수치를 못 보게 되는 것.
- 신뢰구간/표본부족/유의성 경고가 차트 전환 중 누락되는 것 (현 `warnings`, `verdict`, `min_games` 표시는 전부 유지).
- 첫 화면 로딩이 느려지는 것 (TERA 번들 1.2MB를 전역 로딩하면 실패).
- 색만으로 정보를 전달하는 것 (U7).

## 3. 제약

- 스택: Vanilla JS + Canvas, 빌드 도구 없음. 모듈은 `boot.js`의 lazy 로더(`lazyLoadSeq`)와 `index.html` 버전 쿼리(`?v=`)로 관리.
- 운영 nginx CSP: `script-src 'self' https://cdn.jsdelivr.net/npm/chart.js@4.4.0/` — TERA는 **self 호스팅**(`static/vendor/`)해야 하며 `unsafe-eval` 없음 → TERA의 `fromSpec`(내부 `new Function`) 사용 금지.
- TERA CHART: `tera-chart.min.js` v7.0.2, IIFE 전역 `TeraChart`, 1.2MB(gzip 387KB), 의존성 0. 소스는 사내망 `http://192.168.10.94:7000/` (작성자 개인 라이브러리, 라이선스 표기 없음).
  - **[사용자]** 사용 결정. **[판단]** 작성자에게 사용 동의 메시지를 남길 것을 권고(사용자 몫).
  - 확인된 API: `animate(canvas, cfg)`, `render`, `update(canvas, cfg, {duration})`, `stop`, `addResizeObserver`, `buildAriaSummaryStats`, `exportAs`, config `onDataPointClick`, `tooltip`, `annotations`, `brush.enabled`. 타입 목록은 `TeraChart.RENDERERS`.
  - 미확인(Phase 0 스파이크에서 검증): bump(→ line + y축 반전으로 구현 예정), forest plot(→ `range-bar` + scatter 오버레이 또는 `mixed`), 한글 폰트 렌더, devicePixelRatio 선명도, 반응형 리사이즈, 파괴(destroy) 시 리스너 누수.
- 프로젝트 규칙(CLAUDE.md): 팀 컬러는 CSS 변수 기반, 대비비 WCAG AA 4.5:1, hover/active/focus 정의, 최소 12px, Chrome/Edge/Firefox 확인, 7인 관점 체크, 캐시 무효화 인지.

## 4. 결정 사항 (How)

### 4.1 라이브러리 구성 **[사용자: TERA 도입] [판단: 세부]**
- `static/vendor/tera-chart-7.0.2.min.js` 로 버전 고정 저장. 상단 주석에 출처·버전·취득일 기록.
- **어댑터 `static/js/tt_charts.js`** (신규, 유일한 TERA 접점):
  - `TTChart.mount(el, spec)` → canvas 생성·DPR 처리·리사이즈 옵저버·다크 테마 기본값·한글 폰트·접근성(`role="img"` + `aria-label` = `buildAriaSummaryStats` 또는 카드 한 줄 해석) 적용 후 핸들 반환.
  - `handle.update(spec)`, `handle.destroy()`.
  - 도메인 프리셋: `TTChart.presets.{bump, forest, dumbbell, quadrant, heatMatrix, waffle, beeswarm, sankey, lollipop, bullet, kpiSpark, ridgeline, timelineGrid, stacked100}` — 화면 코드는 프리셋만 호출, TERA config를 직접 만들지 않는다.
  - 다른 모듈은 `TeraChart` 전역을 직접 참조 금지 (교체 가능성 보장).
- 로딩: 인사이트·팀·선수·예측 탭의 **최초 진입 시 lazy 로드** (`lazyLoadSeq`에 `tera`·`tt_charts` 추가). 전술판 첫 화면에는 로드하지 않는다.
- Chart.js: 전 화면 이관 완료(Phase 4) 후 제거, CSP의 jsdelivr 항목도 함께 제거. 그 전까지 공존.

### 4.2 레이아웃 — A안 리그 대시보드 **[사용자: A안] [판단: 세부 배치]**
공통 대시보드 셸(인사이트 심화 탭, 팀 분석에 적용; 선수·예측은 셸의 카드 문법만 적용):

```
┌ KPI 스트립 (4칸) ──────────────────────────────┐   ← 큰 숫자 + 변화량 + 스파크라인
├ 테마 칩: 전체 | 흐름·운 | 전술 | 스쿼드 운용 | 세트피스·수비 ┤
├ 카드 그리드 (12-col, 1280px 기준 3열) ─────────────┤
│  [L: 8col 핵심]        [S: 4col]                │   ← 중요도별 L(8)/M(6)/S(4) 폭
│  [M: 6col]     [M: 6col]                        │
└────────────────────────────────────────────────┘
```
- 카드 구성: 헤더(아이콘·제목·질문) → **한 줄 해석**(기존 `insTake()` 결과를 강조 박스로) → 차트 → `근거 보기 ▾`(기존 표 + `ins-method` 방법론 + 경고).
- 카드 우상단: K1|K2 세그먼트 토글(리그 '전체'일 때만 노출) — 두 리그 연속 출력 제거.
- 테마 칩은 카드 필터(클라이언트 측). 선택 상태는 URL hash 또는 localStorage(try/catch)로 유지.
- 스토리 피드 C안의 요소 차용 **[판단]**: 인사이트 심화 탭 KPI 스트립의 4칸 중 1~2칸을 '리그 화제 포인트'(storylines API) 상위 항목으로 채움. 별도 히어로 줄은 만들지 않음.
- 반응형: ≥1280 3열, 900~1279 2열(L은 전폭), <900 1열.
- 카드 최대 높이: 차트 영역 고정 높이(L 320px / M 260px / S 200px)로 그리드 정렬 유지.

### 4.3 시각 규칙 **[판단]**
- 색: 팀 = 기존 팀 컬러 CSS 변수(`primary`) 사용, 대비 부족 팀 색은 차트 위에서 밝기 보정 + 외곽선. 의미색 = 좋음 `--tt-pos`(녹), 나쁨 `--tt-neg`(적), 중립 `--tt-neutral`(회). 강조 대상 외에는 회색(focus+context).
- 색 외 보조 부호: ▲▼ 기호, 점 모양(●■), 직접 라벨 — 범례 의존 최소화.
- 불확실성: 신뢰구간은 항상 선/띠로 표시, 표본 부족은 빗금 또는 흐림 + "표본 부족" 라벨.
- 모션: 최초 진입 `animate` 400ms 이내, 필터 변경 `update` 300ms. `prefers-reduced-motion` 시 `render`(정적).
- 툴팁: 팀명 + 핵심 수치 + 표본 수(n). 숫자 포맷은 기존 화면과 동일 자릿수.
- 상호작용: 팀 요소 hover → 같은 카드 내 동일 팀 강조. 클릭 → 기존 동작 유지(선수 드로어, 팀 분석 이동 등).

### 4.4 성능
- 카드 차트는 IntersectionObserver로 화면에 들어올 때 렌더(심화 탭 18장 동시 렌더 금지).
- 탭/필터 전환 시 이전 핸들 `destroy()` — 기존 `destroyChart()` 패턴을 어댑터로 대체.

### 4.5 API 필드 추가 (additive only) **[사용자: 허용] [판단: 목록]**
원칙: 기존 키 이름·타입·값 불변, 새 키만 추가. 통계는 서버에서 계산하고 `qa_check.py`에 새 필드 존재·범위 검증을 추가. 응답 형태가 바뀌므로 `@cached_response` 캐시는 배포 후 재시작으로 자연 갱신(별도 조치 불필요, 단 로컬 확인 시 서버 재시작).

### 4.6 단계 게이트·대체 규칙 **[판단]**
- **Phase 0은 관문**: 핵심 프리셋 5종(bump, forest, dumbbell, quadrant, heatMatrix) 중 **2개 이상** 품질 미달이면 TERA 도입 범위를 재협의(사용자 보고). 레이아웃·카드 개편(§4.2)은 라이브러리와 무관하게 진행.
- 개별 프리셋 미달 시: 어댑터 내부에서 Canvas 직접 구현 → 불가하면 Chart.js 유지.
- **Chart.js 제거는 조건부**: Chart.js 대체 프리셋이 0개일 때만 Phase 4에서 제거 + CSP 정리. 하나라도 남으면 유지하고 CSP도 유지.

표기: 현재 → 변경. **[사용자]** 표시는 사용자가 고른 차트, 나머지는 [판단].

### 5.1 인사이트 (`insights.js`)
| 카드 | 질문 | 현재 | 변경 |

| 휴식일·연전 | 짧은 휴식이 손해? | 막대+CI 선 | **[사용자] Forest plot** (3개 패널: 간격 / 홈원정 격차 / 연전) |

| 세트피스 공수 | 세트피스 강약? | 표 | **사분면 산점도**: x=생산, y=허용(반전), 4분면 라벨 |

| 득점 의존도 | 에이스 의존? | 막대 | **Waffle** (팀 선택 시) + 리그 전체는 100% 누적 막대 정렬 |
| 선발 로테이션 | 많이 바꾸면 지나? | 표 | **타임라인 그리드**: 팀 × 라운드, 진하기=교체 수, 테두리/기호=승무패 |
| 경기 상황별 성적 (탭) | 앞설 때 지키나? | 표 | **[사용자] Dumbbell**: 앞설 때 PPG ↔ 뒤질 때 PPG |
| 득점 직후 실점·반격 (탭) | 골 넣고 무너지나? | 표 | **Sankey**: 득점 → (10분 내 추가골 / 변화없음 / 실점) |
| 패스 허브 의존도 | 한 명에게 쏠리나? | 막대 | **Lollipop**(팀별 상위 1인 점유율) — 네트워크는 팀 분석 패스네트워크 탭에 이미 있음 |
| 승부처 해결사 | 결정적 골은 누가? | 리스트 | **Beeswarm**(후반 75분+ 결정골 분포) + 상위 5 라벨 |
| 슈팅 인사이트 | — | 리스트 | Bullet chart(실제 골 vs xG) |
| 수문장 | — | 리스트 | Bullet chart(실점 방지 vs 기대) |
| 듀얼 지배 | — | 리스트 | Lollipop(승률, 리그 평균 기준선) |
| TOP 퍼포머(랭킹 탭) | 누가 최고? | 표+미니막대 | 표 유지 + 상단 부문 카드에 **Beeswarm**(포지션 내 백분위 분포 속 1위 위치) |
| 카드 순위(규율 탭) | — | 표 | 표 유지 + 상단 팀별 **100% 누적 막대**(경고/퇴장) |

## 6. 단계 (각 단계 = 독립 배포 가능)

| Phase | 내용 | 완료 기준 |
|-------|------|----------|
| 0 | 벤더 추가 · `tt_charts.js` 어댑터 · 프리셋 스파이크(bump, forest, dumbbell, quadrant, heatMatrix) · 대시보드 셸 CSS/카드 컴포넌트 · lazy 로딩 | 스파이크 페이지에서 5개 프리셋이 실데이터로 렌더, 한글·DPR·리사이즈·destroy 검증, 운영 CSP 하에서 콘솔 에러 0 |
| 1 | 인사이트 3개 탭 전환 | 심화 탭 ≤ 5화면, 모든 경고/표본/유의성 표기 유지, 근거 표 접기 동작 |
| 2 | 팀 분석 + 팀 비교 | §5.2·5.3 반영 |
| 3 | 선수 3모듈 | §5.4 반영 |
| 4 | 예측 + 경기 리포트 · (조건부) Chart.js 제거 · CSP 정리 | §4.6 조건 충족 시 Chart.js 참조 0 + CSP 정리, 아니면 남은 사용처 목록 보고 |

API 필드 추가(§4.5)는 그 필드를 쓰는 화면의 Phase에서 함께 수행: A1·A2·A4·A5·A6·A9 → Phase 1, A3·A7 → Phase 2, A8 → Phase 3.

각 Phase 종료 시: `qa_check.py` 통과, Playwright 스크린샷(1440×900, 1280, 900) 전/후 비교, Chrome/Edge/Firefox 확인, 7인 관점 체크, `index.html` 스크립트 `?v=` 갱신, history 기록.

## 7. 빌더에게 맡기는 것
- 프리셋 내부 TERA config 세부(축·여백·폰트 크기), 툴팁 문구 형식.
- 카드별 L/M/S 크기 배정의 미세 조정(§4.2 원칙 안에서).
- 실점 약점 지도 Canvas 구현 방식(경기장 비율·구역 분할은 기존 API 응답의 구역 정의를 따른다).
- TERA로 구현이 불가능하거나 품질 미달인 프리셋이 Phase 0에서 확인되면: 해당 프리셋만 어댑터 내부에서 Canvas 직접 구현 또는 Chart.js 유지로 대체하고 사용자에게 보고.
