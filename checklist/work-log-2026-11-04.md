## 3. 확정된 사실 (다시 조사하지 말 것)
- **공식 `playerDetail.goal`은 추가시간 득점 등을 일부 빠뜨린다** (정규시간 1% 누락, 90분 이후 8~14%, 전체 득점의 약 2.5%). 공식 API를 다시 호출해도 동일 → 공식 원본 한계(우리 수집 문제 아님).
  - 대응: 공식 리포트 득점은 `_kpm_goal_adjust`로 **경기·팀 단위 부족분 안에서만** 경기 기록(goal_events)으로 보정. 단순 `max(공식, 경기기록)`은 "득점>스코어" 경기를 9→29건으로 늘려 폐기함(공식·경기기록이 득점자를 다르게 적은 경기에서 이중 집계).
  - 결과: 보정 28선수-경기 +29골, 원본 불일치 35→12경기.
- **남은 12경기 중 9건은 오류가 아니다**: 공식이 슈터에게 준 골을 SofaScore는 상대 자책골(굴절)로 기록 → 점검식(공식+자책골=스코어)이 이중 계산. **QA 식을 "공식합==스코어 또는 공식합+자책골==스코어"로 허용하게 고치면 된다(아직 미수정).**
- **나머지 3건은 실제 누락**: 백가온(15403792, 수집 필터 탓 → fill-missing으로 해결), 조진혁(15403802)·이지훈(15403893)은 **공식 응답 자체가 비어 있음**(공식 쪽 누락, 우리가 못 고침).

## 4. 알아둘 함정
- PowerShell에서 원격 명령에 따옴표가 섞이면 깨진다 → 스크립트를 base64로 보내 `echo $b64 | base64 -d | bash` 방식 사용(이 세션에서 쓴 방법). Git Bash의 ssh는 한글 경로를 못 읽으므로 ssh/scp는 PowerShell로.
- Git Bash `curl -o /tmp/..`는 실패했음(대신 PowerShell `Invoke-WebRequest`).
- `gh run list`는 push 직후엔 이전 실행을 보여줄 수 있음 → 몇 초 후 조회.
- QA를 운영 DB 복사본으로 돌리는 법: 스크래치에 폴더를 만들고 `players.db` 하드링크 후 `PYTHONPATH=crawlers`로 `qa_check.py` 실행(서버는 같은 복사본으로 띄움).
- 테스트 서버는 `threading.Thread.start`를 import 동안만 막고(워밍업·스케줄러 차단) 복원한 뒤 `app.run`.
